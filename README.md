# 🛡️ RuCode — Клиент под защитой | Сбер

> Прогноз уровня страховой защиты клиента: ансамбль LightGBM, HistGradientBoosting и CatBoost.

Моё решение задачи **D. PRO «Клиент под защитой»** от Сбера на RuCode.
Лучший результат на открытом лидерборде — **84.89 балла**.

[Страница задачи](https://official.contest.yandex.ru/contest/98289/problems/D/)

---

## 🎯 Описание задачи

По данным о клиенте нужно определить уровень его страховой защиты — число от **0 до 100**.

Данные объединяют несколько групп признаков:

| Группа | Примеры |
|---|---|
| Социально-демографические | Возраст, образование, семейное положение |
| Финансовые | Доход, кредитный рейтинг, платёжная дисциплина |
| Имущество и кредиты | Стоимость жилья и автомобиля, ипотека |
| Страховые продукты | Действующие полисы, виды страхования |
| История обращений | Количество и стоимость страховых случаев |
| Цифровая активность | Использование приложения, двухфакторная аутентификация |
| Региональные риски | Криминогенность, природные и киберриски |

В обучающей выборке **10 000 клиентов**, в открытом и закрытом тестах — по **2 000**.
Целевая переменная — `protection_score`, метрика задачи — **RMSE**.
`customer_id` нужен только для формирования ответа и не используется как признак.

---

## 🏗️ Архитектура решения

Я использую все **59 исходных признаков** и ансамбль из **45 моделей**.

```text
                         Данные клиента
                               │
             ┌─────────────────┴─────────────────┐
             ▼                                   ▼
    Числа: заполнение медианой          Категории: строки
    Категории: One-Hot Encoding         Числовые NaN сохраняются
             │                                   │
       ┌─────┴──────────┐                        │
       ▼                ▼                        ▼
 LightGBM × 15     HGB × 15                 CatBoost × 15
       │                │                        │
     22.5%            67.5%                    10%
       └────────────────┼────────────────────────┘
                        ▼
              Взвешенное усреднение
                        ▼
             protection_score ∈ [0, 100]
```

### LightGBM и HistGradientBoosting

Для каждого семейства обучаются 15 моделей с разными seed. Каждая модель получает
свою случайную подвыборку **85% строк без возвращения**. При построении деревьев
используется случайный выбор **80% признаков**.

| Параметр | LightGBM | HistGradientBoosting |
|---|---:|---:|
| Моделей | 15 | 15 |
| Деревьев в модели | 200 | 250 |
| Learning rate | 0.05 | 0.05 |
| Максимум листьев | 15 | 15 |
| Минимум объектов в листе | 30 | 20 |
| L2-регуляризация | 3 | 3 |
| Доля признаков | 0.8 | 0.8 |
| Доля строк | 0.85 | 0.85 |

Числовые пропуски заполняются медианами обучающей выборки. Категориальные признаки
кодируются через `OneHotEncoder(drop="first", handle_unknown="ignore")`.
Предобработка обучается до выбора подвыборок, на всей доступной обучающей части,
и сохраняется вместе с ансамблем.

### CatBoost

| Группа | Моделей | Деревьев | Внутренний вес одной модели |
|---|---:|---:|---:|
| Plain | 10 | 298 | 0.05 |
| Ordered | 5 | 350 | 0.10 |

Общие параметры: `depth=7`, `learning_rate=0.05`, `l2_leaf_reg=3`, `loss_function="RMSE"`.
Все CatBoost-модели обучаются на полном train.
Категории передаются напрямую, пропуски в категориях заменяются строкой `missing`.
Числовые пропуски обрабатываются через `nan_mode="Min"`.

### Итоговый прогноз

```text
prediction = 0.225 × LightGBM + 0.675 × HGB + 0.10 × CatBoost
```

Внутри семейств LightGBM/HGB каждый прогноз ограничивается диапазоном 0–100,
после чего берётся среднее. Для CatBoost сначала усредняются прогнозы с внутренними
весами, затем применяется ограничение. Итоговая смесь также ограничивается 0–100.

## 📊 Развитие решения

| Вариант | Балл на открытом лидерборде |
|---|---:|
| Ансамбль CatBoost | 75.64 |
| LightGBM + HistGradientBoosting | 80.94 |
| Добавление CatBoost | 82.74 |
| По 15 моделей LightGBM/HGB со случайным выбором признаков | 84.39 |
| Дополнительные подвыборки 85% строк | 84.60 |
| Финальные доли семейств | **84.89** |

Основной прирост дали усреднение моделей и подвыборки строк и признаков.
Локальная валидация не всегда совпадала с результатами открытого теста,
поэтому при выборе финального варианта я учитывал результаты посылок.
**84.89 — балл открытого лидерборда, а не значение RMSE.**

```text
data/
├── hard_train.csv
├── hard_test.csv
└── hard_test closed.csv
```

## 🚀 Быстрый старт

Python **3.11**, обучение и предсказание работают на CPU.

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate

python -m pip install -r requirements.txt
```

### Предсказание с готовыми весами

```bash
python predict.py --test data/hard_test.csv --output-dir submissions_public
```

Для закрытого теста:

```bash
python predict.py --test "data/hard_test closed.csv" --output-dir submissions_private
```

Результат — `submission_seed_995605796.csv` в указанной папке.
Предсказание загружает веса из `weights/` и не запускает обучение.

### Обучение с нуля

```bash
python train.py --train data/hard_train.csv --model-dir retrained_weights
python predict.py --test data/hard_test.csv --model-dir retrained_weights --output-dir submissions_public
```

Те же операции доступны через единую точку входа:

```bash
python main.py train --train data/hard_train.csv --model-dir retrained_weights
python main.py predict --test data/hard_test.csv --model-dir retrained_weights --output-dir submissions_public
```

## 🔒 Воспроизводимость

В `recipe.json` сохранены список признаков, веса компонентов и seed.
Seed семейств LightGBM и HGB — `356220533` и `928098952`.
Из них детерминированно генерируются seed 15 моделей каждого семейства;
все seed CatBoost перечислены отдельно. Seed конфигурации в имени ответа — `995605796`.

Обучение читает только переданный train. Преобразования признаков сохраняются
вместе с весами, при предсказании повторно не обучаются.
В исходной среде Python 3.11 полное переобучение воспроизводило CSV побайтово;
на другой платформе возможны небольшие численные различия.

## 📄 Формат ответа

CSV содержит два столбца:

```text
customer_id,protection_score
```

Порядок клиентов сохраняется из тестового файла. Значения `protection_score`
находятся в диапазоне 0–100.
